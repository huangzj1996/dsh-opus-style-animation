# v1 直带风格原文，不编译成生成指令

**Status**: accepted (2026-10-31)

本 effort 早期把「插件把每份 `## 风格提示词` 载荷编译成带交付契约的生成指令（骨架、`drawScene(t)` 纯函数、六件产物、四档闸门），会话里的 agent 只填 `<scene>`」当作质量杠杆。2026-10-31 的讨论把它换成「风格卡片启动器」：点卡片 → 用 `uiWorkspace.startSession` 开一个新会话 → 把**卡片 md 原文**（加一行任务说明与可选主题）作为草稿带进去，由那个会话里的 agent 自由生成。v1 不编译、不装配、不跑闸门。

## 为什么

- 341 份原文结构差异极大：25 份带可运行参考实现、59 份是 11 节英文规约、248 份是一句话、9 份是空卡。装配器必须按四类分别处理，而用户要的是「像挑字体一样挑风格」的即时入口。
- 编译载荷能把确定性锁进插件，代价是任何风格调整都要改插件；直带原文把「生成什么」交回会话与模型，插件与提示词库解耦（上游更新只需换内置的 341 份原文）。
- 337/341 份是灵感型——契约能约束的是卫生（无 `Math.random`、t 纯函数），约束不了「像不像」，而 v1 的目标只是把链路跑通。

## 考虑过的替代

- **继续编译载荷**（原路线）：质量下限更高，但 v1 交付面翻倍（装配器 + 骨架 + 闸门 + 播放器），且 337/341 份没有可执行规约可依。
- **内置 catalog + 运行时按需拉取原文**：包体小，但离线不可用、首次点击要网；v1 只本机自用，1.40 MB 全量内置更省事。

## 后果

- 地图上契约系的决策（#5 / #13 / #6 / #8 / #2）与载荷编译票 #18 不再施工，只作历史知识；要恢复是一次新的 effort。
- 质量不再由插件保证：产出好坏取决于会话内模型的工程素养，「Opus 5.5 级」降为期望而非验收项。
- 播放器与闸门的观察/验证能力一并退场；用户要看得自己打开 `animations/<slug>/index.html`。
